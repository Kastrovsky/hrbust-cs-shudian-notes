# 使用说明 · 把这份资料交给你的 Agent

> 这份文件写给**下载了这个仓库、想让自己的 AI Agent 接着维护它**的人。
> 目标很具体：**clone 下来 → 装一次技能 → 你的 Agent 就能按原作者同一套逻辑干活，并且越用越准。**
>
> 只想读书、不打算改东西？那你不用装任何东西，直接看 [README](../README.md) 就行。

---

## 0. 一句话版本

```bash
git clone <仓库地址> shudian
cd shudian
python agent/skills/skill-router/scripts/quick_validate.py    # 确认技能包完整
```

然后把 `agent/skills/` 下两个目录安装到你自己 Agent 的技能目录（见 §2），
再把仓库根目录丢给 Agent，让它先读 `AGENTS.md`。完事。

---

## 1. 你提的三条要求，分别由什么满足

| 要求 | 实现物 | 说明 |
|---|---|---|
| ① 能用上原作者做的技能 | `agent/skills/skill-router/`（12 个文件）<br>`agent/skills/shudian-maintain/` | 前者负责"开工前先判断该用哪个技能"，后者是**本仓库专用**的维护手册（六段骨架、台账、配图/公式硬约束、校验命令、playbook） |
| ② 和原对话相似的操作逻辑 | [AGENTS.md](../AGENTS.md) + `shudian-maintain` | 铁律、六段骨架、七个 playbook、八个已知坑，全是原会话里真实踩过并固化下来的 |
| ③ 装到本地后能持续优化、Agent 自己读得懂 | [讲义审校规范_通病清单.md](../讲义审校规范_通病清单.md) + §5 的迭代机制 | 台账是"会长的文档"：每次改动都必须登记一条真实案例；技能本身也写了怎么继续改自己 |

**关键点：这套东西不依赖原作者。** 技能里没有任何盘符路径、没有个人信息，换机器直接可用（如果看到 `<技能目录>` 这种尖括号占位，就是要你替换成本机路径的意思）。

## 2. 安装技能（三种方式，选一种）

技能的本质就是**一个带 YAML front-matter 的 `SKILL.md` + 可选的 scripts/references**。放在 Agent 能扫到的技能目录里，它就会被识别。

### 方式 A：软链接（推荐，改仓库＝改技能）

仓库更新后技能自动跟着更新，不用重复复制。

**Windows（PowerShell，管理员不必需，但目录要存在）**

```powershell
$dst = "$env:USERPROFILE\.workbuddy\skills"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
New-Item -ItemType Junction -Path "$dst\skill-router"     -Target "<仓库路径>\agent\skills\skill-router"
New-Item -ItemType Junction -Path "$dst\shudian-maintain" -Target "<仓库路径>\agent\skills\shudian-maintain"
```

**macOS / Linux**

```bash
mkdir -p ~/.workbuddy/skills
ln -s "<仓库路径>/agent/skills/skill-router"     ~/.workbuddy/skills/skill-router
ln -s "<仓库路径>/agent/skills/shudian-maintain" ~/.workbuddy/skills/shudian-maintain
```

> 用别的 Agent（Claude Code / Cursor / 自建框架）就把目标目录换成它约定的技能位置，`.claude/skills` 之类的，逻辑一样。

### 方式 B：直接复制（不想留链接）

```bash
cp -r agent/skills/skill-router     ~/.workbuddy/skills/
cp -r agent/skills/shudian-maintain ~/.workbuddy/skills/
```

代价：仓库更新后要重新复制一次。

### 方式 C：什么都不装

直接把仓库当上下文，让 Agent 读 `AGENTS.md` + 台账 + 目标文件。能干活，但少了"开工前先判断该用哪个技能"和"每次改动自动过一遍检查清单"这两层保险。

### 装完验证

```bash
python <技能目录>/scripts/quick_validate.py shudian-maintain
```

输出 PASS 即可。它会检查 front-matter 两个必填字段、正文长度、以及文档里引用的文件是否真的存在。
**如果 Agent 是常驻进程（如 WorkBuddy / IDE 插件），要完全退出并重启才能扫到新技能。**

### 可选：装上"提交前自动提示"的钩子

`skill-router` 自带一个钩子安装器，挂到 `UserPromptSubmit` 上，每条消息进来先跑一次技能匹配，命中就提示 Agent 加载：

```bash
python <技能目录>/skill-router/scripts/install_hook.py           # 安装
python <技能目录>/skill-router/scripts/install_hook.py --check    # 只检查
```

脚本会先备份 `settings.json` 再合并写入，重复跑不会装两遍。**换机器或配置被重置时重跑一次即可。**

## 3. 把仓库交给 Agent：第一句话怎么说

不要只说"帮我改这份资料"。给它一个开场约束，之后的每一轮它都会自己按流程走：

```text
这个仓库是哈尔滨理工大学《数字电路与逻辑》的复习资料。
先读 AGENTS.md 和 讲义审校规范_通病清单.md（重点看 §九 变更记录最后三行），
再按 agent/skills/shudian-maintain 的规矩动手。
硬约束：只增不删、每次改动登记台账、数学模式禁汉字、配图必须完整、提交前跑凭据闸门。
改完告诉我：改了哪些文件、对应哪个通病编号、校验结果。
```

### 首次接管的三步

1. **摸现状**：`git log --oneline | head -20`，再看台账 §九 最后三行 —— 最近三次改动的原因与判据，比读全文快。
2. **跑一遍基线校验**：`python scripts/check_links.py`。先确认"我接手时就是 0 断链"，之后任何断链都是自己弄断的。
3. **做一件最小改动**（比如给某一节补一句易错点），完整走一遍"改 → 校验 → 登记台账"，把流程跑顺再动大件。

## 4. `agent/` 里到底有什么

```
agent/
├── 使用说明.md                       ← 你正在读的这份
└── skills/
    ├── skill-router/                 技能路由（通用，不限于本仓库）
    │   ├── SKILL.md                  路由表：什么任务该加载哪个技能
    │   ├── references/
    │   │   ├── skill-index.md        已装技能的索引
    │   │   ├── distill-trigger.md    什么经验值得沉淀成技能
    │   │   └── distill-ledger.md     沉淀台账（**原作者的个人记录，当格式范例看**）
    │   └── scripts/
    │       ├── match_skill.py        一句话匹配技能（有自检：--selftest）
    │       ├── on_prompt.py          钩子入口，自动注入匹配结果
    │       ├── install_hook.py       幂等安装/检查钩子
    │       ├── refresh_index.py      重建技能索引
    │       ├── overlap_check.py      新技能与现有技能的重合度检查
    │       ├── quick_validate.py     技能包完整性自检
    │       └── selftick.py           任务计数与巡检提示
    └── shudian-maintain/             本仓库专用
        └── SKILL.md                  六段骨架 / 铁律 / 校验命令 / 七个落点 / 台账规则
```

> **关于 `distill-ledger.md`**：它是原作者自己在别的项目上积累的技能沉淀记录，随包附上是**当格式范例**用的。你不必沿用里面那些条目，建议改成自己的。

## 5. 持续优化：三个环

这套设计里"优化"不是靠灵感，是三个闭环：

### 环一：台账（每次改动必转一圈）

用户提要求 → 判断属不属于已登记的通病 → 属不属于都登记 → 下次同类问题直接照编号修。
编号永不复用，所以"这个坑以前踩过"是可查的，而不是靠记忆。

### 环二：技能（重复出现的判断才升级）

- **单次事故** → 只写台账（案例 + 修法）。
- **同类问题 ≥2 次** → 才写进 `shudian-maintain/SKILL.md`，变成一条带判据的约束。
- 改完自检：`python <技能目录>/scripts/quick_validate.py shudian-maintain`。

判断标准很简单：**"下次遇到同样情况，光看台账能不能推出正确做法？"** 能就停，不能才升级。

### 环三：校验（每次交付前必跑）

自动化能判的一律交给脚本，不靠"我记得改过"：

| 命令 | 判据 |
|---|---|
| `python scripts/check_links.py` | 0 断链（相对链接 + 图片引用） |
| `python scripts/check_secrets.py --history` | 0 命中才允许 commit / push |
| `grep -rn "Hmm\|等一下\|需重算\|我算错" --include=*.md .` | 0 命中 |
| KaTeX 严格模式全量（命令见 AGENTS.md §4） | 0 失败 |
| `提取/verify_fold.py`（本地有才跑） | 只增不删 = True |

## 6. 常见问题

**脚本跑不起来：`ModuleNotFoundError`**
`check_links.py` 只用标准库，任何 Python 3.8+ 都行。`recrop_*.py` 需要 `pillow` / `numpy`（重裁原卷图还要 `python-docx` / `pymupdf`）：

```bash
pip install pillow numpy python-docx pymupdf
```

**图全是裂的**
八成是 `.gitignore` 拦了图片。本仓库用"默认拦 `*.png` + 逐目录白名单放行"的策略，新增配图目录必须在 `.gitignore` 里加一行 `!新目录/*.png`，否则图片没进仓库。

**公式显示成 `[Math Processing Error]`**
数学模式里有汉字或顿号。改为 `_{\text{原}}`，或把并列项拆成 `$A$`、`$B$`。

**折叠块里的公式/表格不渲染**
`<details>` 之前、`<summary>` 之后、`</details>` 前后少了空行。

**Gitee / GitHub 上 mermaid 不渲染**
所以"必须能看"的图一律导出 PNG，不用 mermaid。

**想离线看，不想依赖平台渲染公式**

```bash
npm i katex markdown-it
node scripts/build_html.js "计算机专业真题/数字电路与逻辑_期末习题集_含答案与解析.md" "输出.html"
```

产出一份 1.7 MB 的自包含 HTML：公式构建期编译、字体内嵌、不联网，双击就能读，也能直接打印。产物已被 `.gitignore` 排除，别提交。

## 7. 不想用了怎么撤

```bash
# 方式 A 装的：删链接（Windows 用 rmdir，别用 del，否则会删掉源目录内容）
rm ~/.workbuddy/skills/skill-router ~/.workbuddy/skills/shudian-maintain
# Windows: cmd /c rmdir "%USERPROFILE%\.workbuddy\skills\shudian-maintain"

# 装过钩子的话，从 ~/.workbuddy/settings.json 的 hooks.UserPromptSubmit 里删掉
# 指向 on_prompt.py 的那一条（install_hook.py 装之前会备份，可直接还原备份）
```

删技能不影响仓库内容，仓库是纯 Markdown，任何编辑器都能读。
