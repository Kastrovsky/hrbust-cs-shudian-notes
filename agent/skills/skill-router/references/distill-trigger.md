# 沉淀触发（Skill Distill Trigger）

> 配套 `skill-router`：回答「**我**什么时候该把这次的做法变成技能」，以及「用户同意后要改哪些地方」。
> 位置：`<技能目录>\skill-router\references\distill-trigger.md`；由 SKILL.md 的「沉淀判定」一节引用。

## 一、核心原则

**触发权在我这边。** 等用户说「做个技能」「以后都这样」= 永远等不到。用户提需求时想的是把这件事做完，不会想「这套流程值得留下来」——那是我的活。

三条不可动摇：

1. **固定节点必检**——T1/T2/T3 到点就跑，不靠灵感。
2. **先交付，后说话**——任务完整做完、成品展示了，才在末尾提一句。不阻塞、不弹窗。
3. **有结论才开口**——自检是每次必做的内部动作，提问只在有结论时发生。没结论就静默，不要为了「表示我在工作」而问。

## 二、三个触发时机

| 标记 | 节点 | 判定范围 | 必做性 |
|---|---|---|---|
| **T1** | 每个带明确指令的任务交付完 | 只看**刚做完的这一件** | 必做，主时钟 |
| **T2** | 同会话累计满 **5 个任务**，或同一件事来回 **≥30 轮** | 扫**全部已完成任务**，找跨任务模式 | 必做 |
| **T3** | ① 用户说「结束／先这样／换个话题」或上下文即将压缩；② 每周日 21:00 自动化「技能提取与创建巡检」（id `da4b19b2`） | 整段对话兜底 ／ 最近 7 天日志 | 必做 |

**关于「定时」**：有两条路，一条在会话内，一条在会话外。

- **会话内用计数**（T2）：每完成一个任务跑 `scripts/selftick.py --tick` 落盘累计（**不靠临场记性**，会话被压缩也不会丢）；到阈值它自己提示做模式扫描，扫完 `--scanned` 清零。会话首个任务前先 `--status`，报「距上次巡检 >7 天」就先 `--audit`。
- **会话外用自动化**（T3 的定时部分）：每周日 21:00 的「技能提取与创建巡检」（id `da4b19b2`）读最近 7 天的工作日志与候选区，**不只是列清单——够格就真的落地**：三问全过 + 同一流程 ≥2 次独立出现 + `overlap_check.py` 查重结论明确时，按「优化现有／合并／新建」执行完整链路（建实体 → junction → `quick_validate.py` → 注册 → 回归 → `overlap_check.py all` → 台账记 `已建`／`已并入`），失败即回滚。证据不足才写进 `<技能目录>\_沉淀候选.md` 标「待判」。**它不需要用户开口，也不需要会话存在**——这是真正意义上的「定时提取并创建」。

两条的分工要说清：**T1/T2 是主力，自动化只兜底**。自动化没有对话现场，看不出"这句话用户改了三遍"这种细节，它能捞到的多是"同类任务又出现了一次"这类粗颗粒模式；所以门槛设得比 T1 高（≥2 次独立出现 + 查重），且**不改现有技能的既有流程段落**。别指望它替代 T1——**每个任务收尾时那 30 秒自检才是根本**。

**T2 的意义**：单次 T1 容易漏。有些模式只有横向看才显形——比如三个不同章节的笔记都走了「先裁图放大读 → 验算 → 重绘 → 并入 → 校验」这一套，单看每一件都像一次性任务，横向看就是个该固化的流程。`handwritten-study-notes` 就是这么来的。

**T3 的意义**：长会话会被压缩，压缩后早期细节就淡了。收尾时把整段过一遍，把它救下来。

## 三、三问（T1 每次都跑）

| 问 | 通过条件 | 不通过时 |
|---|---|---|
| **可复现** | 换个输入物（另一本书／另一门课／另一批题／另一个仓库）还能跑 | 一次性任务，写日志了事 |
| **非显然** | 装的是用户偏好、踩过的坑、阈值、命名约定、校验方式 | 通用能力能覆盖，不建 |
| **边界清** | 说得清什么情况**不**适用 | 边界糊 → 说明还没想透，先改现有技能里最接近的那条 |

三问全过 → 进第四节决定「新建」还是「并入」。有一条不过 → 按「四档落地」下沉，**不建技能**。

## 四、加速信号（不是闸门）

三问之外，这些迹象说明「这次值得留下」。**出现任意两条即可直接提议**：

| 信号 | 判据 | 为什么算信号 |
|---|---|---|
| 用户给过明确规格 | 「以后都这样 / 按这个标准 / 必须… / 不要…」，说的一**类**任务 | 用户已经把验收标准说出来了，等价于替我写完了一半技能 |
| 同一处往返 ≥3 轮 | 结构级修订，不含错别字 | 反复改的地方，就是我第一次没做对的地方 |
| 用户否掉默认做法 | 并给了替代方案 | 我的默认值错了，这个纠正值得固化 |
| 同类返工 ≥2 次 | 一次任务里同类型错误出现两次以上 | 说明流程缺了一道检查 |
| 定稿与初版差异大 | 且每条改动理由能归成规律 | 规律本身就是技能内容 |

**关键提醒**：信号全没出现，三问也可能全过。比如某次任务自己跑通了一套从没写下来的步骤，用户只是说「做完了，不错」——这种情况照样该提议。信号是加速器，不是闸门。

## 五、什么时候不说话

自检做，但下列情形一句都不提：

- 纯问答、概念解释、闲聊、看一眼文件、查个数据；
- 任务一次性，没有可复用步骤；
- 已有技能完全覆盖，本次没新增约束或纠正；
- **台账里这个候选已提过并被拒**（查 `references/distill-ledger.md`）；
- 用户明显在赶进度、连着下达新指令——记下，等 T2 或 T3。

不要「每轮结尾都请示一句」。那会让用户学会无视这句话，等于把机制废掉。

## 六、落地与告知（默认不问，末尾一行）

**发起权、决策权都在我这边。** 用户 2026-11-10 说得很直白：「不是我说了你才做，是你自己的」。2026-11-12 再放一级：「有用的正确的直接优化或创建就行」——所以**连改现有技能也不必先问**了。

| 情形 | 动作 |
|---|---|
| 三问全中，新建技能或**优化现有技能** | **直接做**，做完末尾告知一行；新建的附「不要就说删」 |
| 三问全中，但证据只有一次（判得勉强） | 不做，记台账 `待定`；同类再出现一次就落地 |
| 用户明确说过不沉淀 | 台账标 `已拒`，**以后不再提**，除非他自己提起 |
| 判下来不够格 | **静默跳过**，只在台账记一行理由，连「没有要沉淀的」都不说 |

告知格式就两行，别写小作文：

> 沉淀：这次跑通的 XX 流程已并进 `yyy`（改了哪几节）；下次同类直接走它。

> 沉淀：新建了 `xxx`（`<技能目录>/xxx`），不要就说删。

**为什么不问**：技能是磁盘文件，建错了一句「删了」就回滚；而每轮都问，用户会学会无视这句话，机制废掉。**真正的成本不是建错，是问太多。**

**动作必须可见**：新建说清路径与用途；改现有 SKILL.md 点明改了哪几节，让用户能一句话否掉。

**跳过也要留痕**：尤其「看着像但不够格」的候选，进 `references/distill-ledger.md` 标理由——不留痕等于下次从零再判一遍。

**不做噪音**：一次会话里连着多个小任务，合并成一条沉淀说明。

## 七、四档落地：先归类，再新建

**默认假设"已经有技能能装下"**，找不到证据才新建。技能库最怕的不是少一个，是三个技能抢同一批触发词——之后每轮都要临时仲裁，比没有技能更慢。

| 档 | 判定 | 动作 | 例子 |
|---|---|---|---|
| ① 归类（首选） | 现有技能覆盖 ≥50% | **改那个 `SKILL.md`**：补判据／补踩坑／扩「何时用」／加触发词，不新建 | 给 `math-formula-audit` 补一条「`$$` 跨行算不算配对」 |
| ② 合并 | 两个技能重叠 ≥50% | 合成一个（留触发词更全的名字），另一份并入后删目录 | 两份笔记类技能并成一个 |
| ③ 新建 | 三问全中 **且** 与现有技能覆盖 <28% | `skill-creator` 建，实体 `<技能目录>\` | `question-bank-crossref` |
| ④ 不建技能 | 只属这个仓库／一次性偏好 | 前者写项目 `MEMORY.md`，后者写用户级 `MEMORY.md` | 「图片必须 `git add -f`」 |

**查重先跑脚本，别凭"我觉得不撞"**：

```bash
python scripts/overlap_check.py candidate "一句话职责" --triggers "触发词1, 触发词2"
python scripts/overlap_check.py all --gate        # 巡检：有重叠返回 1
```

口径：**≥0.50 优化它／0.28~0.50 读对方边界再定／<0.28 可新建但仍要验触发词不撞车**。
脚本量的是字面覆盖，不是能力覆盖——分数只是证据之一，最后仍要我判：**「这个能力是不是已经有人管了？」**

## 八、落地后的更新链路

1. **建实体**：`<技能目录>\<name>\`，`SKILL.md` 带 `name` / `description` / `agent_created: true`；有校验逻辑就放 `scripts/`。
2. **建联接**：PowerShell `New-Item -ItemType Junction -Path "<你的技能目录>\<name>" -Target "<技能目录>\<name>"`，否则 Skill 工具发现不了。
3. **校验结构**：`quick_validate.py <dir>` → 必须 `Skill is valid!`。
4. **三处注册**：
   - `skill-router/SKILL.md` 路由表补一行；
   - `skill-router/SKILL.md` 「触发词」表补一行（≤13 个词，长词优先）；
   - 用户级 `MEMORY.md` 只维护「一键匹配 + 撞车仲裁」，**不再复制触发表**（两处有表必有一处过期）；真是多次撞车才补「撞车仲裁」。
5. **加回归用例**：往 `scripts/match_skill.py` 的 `SELFTEST_CASES` 里加「触发它的用户原话 + 正确技能名」。
6. **刷新与回归**：
   ```bash
   python "<技能目录>/scripts/refresh_index.py"
   python "<技能目录>/scripts/match_skill.py" --selftest
   python "<技能目录>/scripts/overlap_check.py" all
   ```
   前者报「未登记到路由表」= 第 4 步漏了；第二个必须全 PASS，命不中就补触发词；第三个看新技能有没有跟别人撞车。
7. **记台账**：`references/distill-ledger.md` 加一行，写清日期、技能名、触发它的那次任务。
8. **留痕**：追加当天工作日志；用 `present_files` 展示新技能的 `SKILL.md`。

## 九、反模式

| 不要做 | 原因 |
|---|---|
| 等用户开口说要建技能 | 他想不到，等不到，机制等于不存在 |
| 每轮结尾都请示一句 | 变成噪音，用户学会无视 |
| 三问没过也建 | 路由表污染，误命中率上升 |
| 已有能力覆盖还建新的 | 两个技能抢同一批触发词，互相打架 |
| 建了不注册、不刷索引 | 下次匹配不到，白建 |
| 只报「沉淀了」不说是什么 | 用户没法复查，等于黑箱 |
| 用户说「不用」后还反复建 | 破坏信任，此后所有落地都被当骚扰 |
