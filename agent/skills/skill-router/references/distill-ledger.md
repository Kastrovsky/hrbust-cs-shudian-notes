# 沉淀台账（Skill Distill Ledger）

> 用途：**防止同一个候选被反复提议**。每次 T1/T2/T3 自检、决定提议之前，先查这张表。
> 规则：**只增不减**，一行一个候选。状态只用四种：`已建` / `已并入` / `已拒` / `待定`。
> 位置：`<技能目录>\skill-router\references\distill-ledger.md`

## 状态含义

| 状态 | 含义 | 后续动作 |
|---|---|---|
| `已建` | 已建为独立技能 | 不再提议；技能失效或需大改时另开一行 |
| `已并入` | 归入了某个现有技能（B 档） | 不再提议 |
| `已跳过` | 判过、不够格（一次性的／通用能力覆盖／边界不清） | 不再重复判；除非出现明显新证据 |
| `已拒` | 用户明确说不沉淀 | **永不再问**，除非用户自己提起 |
| `待定` | 用户说「先记着」 | 下个 T2 再说一次，**仅一次**，之后转 `已拒` |

## 怎么写新行

1. **候选流程**写「动词 + 对象 + 关键判据」，不要只写名词。反例：`笔记`。正例：`手写笔记风格的章节改写（四字段块 + 例题随行）`。
2. **落点**写具体文件或技能名，不写「记忆里」这种含糊说法。
3. **触发它的那件事**写清用户当时要干什么——半年后回看，靠这一列才能判断该不该复用。
