# 数电讲义仓库 · 维护技能

## Overview

这个仓库不是普通笔记，它有一套**已经付过学费的规矩**：每一条硬约束背后都有一次真实踩坑（图被切了四轮、公式全篇报错、答案折叠后整块不渲染、搬目录打断 300 条链接）。所以本技能的作用不是"教你怎么写 Markdown"，而是**让你别把已经修好的东西再弄坏**。

开工前必须先读两份文件（它们才是权威，本技能只是索引）：

| 文件 | 作用 |
|---|---|
| `AGENTS.md` | 接手总说明：结构、约定、铁律、playbook、已知坑 |
| `讲义审校规范_通病清单.md` | 台账：A/B/C/D 四类通病，每条带编号与真实案例。**改了什么就必须在这里留痕** |

人读版本在 `README.md`，给读者看的，不用管。

---

## 一、开工三步（顺序不能换）

1. **读台账最后三行 §九 变更记录** —— 那里写着最近三次改动的原因与判据，比读全部内容快。再 `git log --oneline | head -20` 看最近动了什么。
2. **判断这次要求属于哪条通病** —— 命中了就补案例到已有编号下，没命中才新开号。判断不清就先按"疑似新问题"处理，改完再定号。
3. **只增不删** —— 在原有内容**之后**追加。原有结论、数值、例题答案一律不动（笔误除外，且要在台账登记）。

## 二、硬约束（违反任一条，改动不算完成）

| 编号 | 约束 | 判据 |
|---|---|---|
| 1 | 只增不删 | `git diff` 里不应出现被删除的结论句、算式、答案 |
| 2 | 每次改动必须登记台账 | 台账 §九 有一行：日期 / 触发原话 / 改了什么 / 校验结果 |
| 3 | 数学模式禁汉字与顿号 | KaTeX `strict:"error"` 全量 0 失败；下标写 `_{\text{原}}`，并列拆成 `$A$`、`$B$` |
| 4 | 配图必须完整 | 四边留白、不切字、不吞邻题、不带页脚；逐张 `ViewImage` 目检 |
| 5 | 提交前过凭据闸门 | `check_secrets.py --history` 0 命中；账号、口令、令牌、绝对路径、姓名学号一律不入库 |
| 6 | 交叉引用必须可点 | 写 `[直达 §x.y 标题](../第N章_xxx/x.y_xxx.md)`，链接文字取目标文件 H1；讲义没写的标"讲义未单列"，**不硬塞不相干链接** |
| 7 | 数值结论必须验算 | 时序、计数、真值表类用 Python 穷举，不靠心算 |

## 三、六段骨架（讲义不可缺段）

```
# N.M 标题（English Name）
## 一、是什么（概念与定位）
## 二、原理与特性
## 三、符号与图形（图文并茂）
## 四、典型例题/应用
## 五、易错点
## 六、知识点总结
```

`第N章_例题与考法解析.md` 例外，用四段：`一、考情概览 / 二、典型例题 / 三、真题考法归纳 / 四、本章必背清单`。

习题类文档每题固定：`题目原文 → 详解 → 知识点总结 → 考点归纳（含章节与直达链接）→ 延伸扩展`。

### 章节号陷阱

卷子里的章号用的是**课堂讲义编号**，与仓库文件序号不同：

- 课堂 §3.4 卡诺图 = `第3章_逻辑门与组合逻辑/3.7_卡诺图化简法.md`
- 课堂第 5 章时序 = 仓库第 6 章
- 课堂第 6 章 555/运放 = 仓库第 7 章

**写链接时以目标文件实际 H1 为准，不要照抄文档里出现的章号。**

## 四、目录职责

| 目录 | 放什么 |
|---|---|
| `第1章…第7章_*/` | 讲义主体：`N.M_主题.md` + `第N章_例题与考法解析.md` + `images/` |
| `计算机专业真题/` | 一切"卷子类"：习题集、4 套练习卷逐题精析、手写笔记速查、真题精解、原卷图 |
| `计算机专业真题/真题精解/` | 历年 A 卷逐题精解（`0N_学年学期_卷别.md`）+ `images/` |

| `scripts/` | 校验与生成工具（见 §五） |

## 五、校验命令（照抄，在仓库根目录跑）

```bash
python scripts/check_links.py        # 相对链接 + 图片引用，0 断链才算过
python scripts/check_secrets.py --history   # 凭据闸门，0 命中才允许 commit / push

# 口语残留必须 0
grep -rn "Hmm\|等一下\|需重算\|我算错" --include=*.md .
```

**KaTeX 全量验证**（改过公式才跑，临时脚本不进仓库）：

```bash
npm i katex
node -e '
const k=require("katex"),fs=require("fs");
let bad=0,n=0;
for(const f of process.argv.slice(1)){
  const t=fs.readFileSync(f,"utf8").replace(/\r\n/g,"\n");
  for(const m of t.matchAll(/\$\$([\s\S]+?)\$\$|\$([^$\n]+?)\$/g)){
    const s=(m[1]??m[2]);n++;
    try{k.renderToString(s,{strict:"error",throwOnError:true})}catch(e){bad++;console.log(f,"→",s.slice(0,60),e.message.slice(0,80))}
  }
}
console.log("公式",n,"失败",bad); process.exit(bad?1:0)' $(git ls-files "*.md")
```

**答案折叠校验**（改过习题集才跑，需本地有 `提取/verify_fold.py`）：判据是"只增不删 = True"、`<details>` 标签 28/28/28。

## 六、各任务的落点（详细步骤见 AGENTS.md §5）

| 用户说 | 怎么做 |
|---|---|
| 补/改某节讲义 | 读原节 → 判通病 → 追加 → Python 验算 → 补直达链接 → 跑校验 → 登记 |
| 图被切了 / 图不完整 | 改 `scripts/recrop_*.py` 顶部的**坐标表**（源页 + 裁剪框 + 抹白矩形），不要手改输出图；裁完逐张目检 |
| 公式报错 | 找数学模式里的汉字或顿号 → 改 `_{\text{…}}` 或拆开 → KaTeX 全量复跑 |
| 答案要能折叠 | 用 details / summary 标签包住答案区；开标签前、summary 后、闭标签前后**必须留空行**，否则块内公式、表格、代码块全部不渲染（台账 C 类，真实踩过） |
| 要一份能离线看的 HTML | `npm i katex markdown-it` → `node scripts/build_html.js "源.md" "输出.html"`；产物 1.7 MB 自包含，`.gitignore` 已排除 |
| 加一套真题 | 原卷进 `源卷/` → 新建 `真题精解/0N_….md` → 裁图 → 在 `00_全部真题索引与考点对照.md` 登记 |
| 搬目录 / 批量改名 | 先算清链接深度（讲义链接是 `../第N章_xxx/…`，图片是 `images/…`）→ `git mv` → 同步改 `.gitignore` 白名单、`scripts/*.py` 硬编码路径、README 目录树 → 跑 `check_links.py` |

## 七、台账登记（最容易被跳过的一步）

1. **判归属**：A 内容正确性 / B 结构完整性 / C 排版可读性 / D 工程交付。
2. **已有编号就补案例**，不要新开号；新开号取该类最大号 +1，**编号永不复用**。
3. **写法必须具体**：三列 `通病 | 真实症状（案例出处）| 修法 / 判据`，案例要写清用户原话 / 具体文件 / 具体数字，**不许写"某次发现图片被切"**。
4. **§九 追加一行**：`| 日期 | 触发（用户原话） | 变更（文件、编号、校验结果） |`。

> 铁律的由来：用户明确要求"每提一个修改要求，必须更新一次台账"。改了文件不登记＝这条改动没做完。

## 八、交付报告模板（别只说"改好了"）

```
改了什么：第4章/4.8_….md 追加「三、符号与图形」缺失的波形图说明
对应通病：B-01（对称面只写一半），已在台账补案例
配图：重裁 2 张，目检四边留白通过
校验：check_links 0 断链 / KaTeX 0 失败 / 口语残留 0
台账：§九 已追加一行
```

## 九、这个技能自己怎么继续长

1. **只改本文件，不改仓库内容。** 技能是"操作方法"，仓库是"产物"，两者不要混。
2. **新踩的坑先记台账，稳了再升级成技能条目** —— 单次事故写台账，重复出现 ≥2 次的判断才写进本技能。
3. **改完做自检**：`python <技能目录>/scripts/quick_validate.py shudian-maintain`（校验 frontmatter 字段、正文长度、引用的文件是否真的存在）。
4. **写清的判据要能被执行**：每条约束后面都要跟一句"怎么验"，否则下一个人（或 Agent）只能靠猜。
5. **不要往技能里写死本机路径**。需要指路时写「仓库根目录的 scripts 目录下那个脚本」，不要写盘符，也不要写成看起来像真实路径的样子——校验器会把它当成"引用了不存在的文件"。
